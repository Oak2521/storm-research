# 0 · 如何使用本文档（给接手的 Claude Code）

**你是谁**：你将升级 oakbylake.com——湖岸橡树（Oak by Lake），一家面向海外华人作者的加拿大中文出版社的网站。

**开工前必读（本仓库 `examples/` 下 4 份源文档，按此优先级）**：
1. `湖岸橡树网站信息架构.md` —— **信息架构唯一真源**（站点树 + 三色状态 + 读者动线 + 页面顺序约定）。本执行方案不另立 IA，一切以它为准。
2. `湖岸橡树未来出版体系方案_升级版.md` —— 战略、客群（GTM）、运营现实解法、承重墙修法。
3. `湖岸橡树竞争分析报告.md` —— 差异化定位（为什么这样写文案）。
4. `湖岸橡树未来出版体系方案研判.md` / `_研判修订版.md` —— 背景与证据（可选深读）。

**最高指令（每一步都用它自检）**：
- **深结构 / 窄门面 / 单漏斗**：站点结构做完整，但只把"信用之书"这一条转化漏斗做成在售、死磕它。
- **展示 ≠ 在售 ≠ 可交付**：页面可以展示愿景，但**只有创始人（一人+AI）当前交付得了的东西，才配一个"购买/咨询"按钮**。
- **诚实即资产**：每一处诚实边界（下架≠销量、认可度告知、WorldCat 表述、无独家）都要显性写出来——它们是转化资产，不是免责小字。

**必须先向人类（创始人）索取的输入**（缺了会卡住，先问再动手）：
- oakbylake.com 的**仓库访问 / 现有构建与部署方式**（域名托管、CI、CMS 或静态站）。
- **两本样书**（《天鹅绝唱》《诗经新注新译》）的封面、书号、上架链接、简介——做首批案例。
- **诗经作者案例**授权与素材（用于「信用之书」样板案例）。
- **支付账号**决策（Stripe / PayPal 是否已注册；见 §6.4）。
- **定价确认**（各套餐前台价，见 §5、§9）。
- **法务核实项**回执（GST/HST、FINTRAC、出版物回流——见 §7、§9，未核实前相关文案用保守表述）。
- **已开发的后台注册管理系统**的代码 / 接口文档 / 访问权限（将融合进本项目——**复用集成，勿重建**，见 §2 第 7 项、§6.7）。

# 1 · 背景与约束（自包含压缩版）

- **主体**：湖岸橡树 Oak by Lake，加拿大注册中文出版社；已出版《天鹅绝唱》《诗经新注新译》两部（此前为免费试水）。
- **运营现实**：**创始人一人 + AI 辅助**；另有《文脉》季刊团队协作。产能有限——这是"窄门面/单漏斗"的根本原因。
- **《文脉》季刊 = 信任引擎**：已运转四年、14 期、有真实作者网络（含高校作者）。它**不追求自身盈利**，作用是把作者关系转成暖线索。网站要让它明显、可投稿、可沉淀作者页。
- **GTM 靶心 = "书作杠杆"客群**：付费意愿不在"书"本身，在"书能撬动的另一门生意或那道门槛"（卖课背书、申博门槛、职业信用、客户信任）。**纯为热爱/纪念出书的人付费意愿低**，是案例/口碑源。文案与漏斗都对准前者。
- **一年跑道**：第一优先是让"信用之书"漏斗跑通、见到真实收入。其余全部次要。

# 2 · Phase 0 · 现状发现（**必做的第一步，先盘点再动手**）

在写任何页面之前，先摸清 oakbylake.com 的真实情况，产出一份"现状 → 目标 IA 差距表"。要回答：

1. **技术栈与部署**：是无代码平台（Squarespace/Wix）、CMS（WordPress）、还是代码仓库（Next.js/Hugo/静态站）？如何构建、如何部署、谁掌握发布权限？
2. **现有页面清单**：现在有哪些页面/导航项？逐一列出 URL、标题、用途、语言（简/繁/英/双语）。
3. **现有内容资产**：已有的文案、图片、案例、《文脉》期刊内容、样书信息、作者资料在哪、什么格式。
4. **表单与支付现状**：有没有咨询表单、邮件订阅、支付/收款能力？
5. **分析与 SEO 现状**：有没有 Google Analytics / Search Console / sitemap / 结构化数据？
6. **品牌资产**：现有 logo、配色、字体、视觉规范（若与本方案 §6.1 冲突，以创始人确认为准）。
7. **已有后台系统（重要）**：创始人已开发一套**后台注册管理系统**，将融合进本项目。盘清它——功能范围（用户/作者注册、账号管理、是否含订单/后台运营）、技术栈、API 与数据模型、认证方式、与前台如何对接。**目标是复用与集成，不是重建**；若与前台技术栈不一致，产出集成方案（API 对接 / 同库 / 反代等）交创始人确认。

**产出**：一张表 `现状页面 → 目标 IA 对应页 → 差距（新建/改造/合并/保留）→ 状态标签🟢🟡⚪ → 优先级`。把它交创始人确认后，再进 Phase 1。

> 开发型接手方：`git clone` 后先读 README/package.json/配置，跑起来本地预览，用站点地图或路由文件列全量页面。
> 内容型接手方：登录平台后台，导出/截屏现有页面结构与文案清单。

# 5 · 逐页构建规格（🟢 优先页）

> 每页统一区块顺序（**页面顺序约定**，全站强制）：
> **① 承接担忧 → ② 能做成什么（结果+情感承诺+案例/样品）→ ③ 正规与可查证证据（含诚实边界）→ ④ 价格（永远最后一屏）→ ⑤ CTA**。
> 每页规格给：目的 / 目标读者 / 区块 / 文案方向与样板句 / 组件 / 验收 / 修法标注；末尾两行给内容型与开发型接手方各自提示。

## 5.1 首页 Home（含「你是谁/你在担心什么」五入口地图）
- **目的**：3 秒内让访客感到态度与温度，并按"我是谁/我在担心什么"自我分流。
- **区块**：① 态度样板首屏（大标题「你的文字，值得被世界看见」+ 一句副文 + 主 CTA〔咨询出版〕）→ ② 五入口地图（学术作者🟢 / 家族记忆🟡 / 海外·文学写作🟢 / 机构·社区🟡 /「我还没想好」🟢）每扇门一句先承接担忧的话 → ③「凭什么信你」信任页入口卡 → ④ Why Oak by Lake（可查证/编辑力/双语，三点）→ ⑤ 精选案例 + 文脉入口 + 页脚。
- **五入口样板句**（承接担忧，非功能罗列）：
  - 学术作者：「让你的著作，经得起追问。」
  - 家族记忆：「有些故事，只有你知道。」
  - 海外/文学：「书出版了，然后呢？」
  - 机构/社区：「为你们的集体记忆，做一份经得起时间的正式记录。」
  - 还没想好：「还没想好，也没关系。」
- **验收**：五入口各自链到对应页；首屏无价格、无表格；移动端五入口不挤成一行。
- **修法标注**：首屏不承诺"评上职称/保证销量"。
- 内容型：先写五入口 5 句 + 首屏 2 句，再排版。｜开发型：首页组件化（Hero / EntryGrid / TrustCard / WhyOak / CaseStrip），入口数据可配置。

## 5.2 信任页「凭什么信你」（**最强转化资产，优先级最高**）
- **目的**：正面回应"这又是个花钱就给印的中介吧"的默认戒备，把可核验资质集中一处。
- **区块**：① 承接怀疑（「担心这又是一家'花钱就给印'的中介？应该担心。」）→ ② 市面四类雷区点名（KDP 冒充海外社/假书号/无实体 Gmail/超低价诱导）→ ③ 我们的不同，逐条可查（加拿大注册出版社名义出版·版权页署出版社非"个人独立出版"；每本书 LAC 法定送存；书目元数据进入全球图书馆数据网络 WorldCat；出版记录/上架链接/合同条款/预收款保护都摆出来）→ ④ 我们也只说真话（上架≠销量；海外专著在国内评审多为补充、认定权在用人单位；AI 检测有误差，所以我们做"真实写作档案"而非"认证"）→ ⑤ CTA。
- **验收**：四类雷区与"我们的不同"一一对应；诚实边界显性成段，不是灰色小字。
- **修法标注（全落这页）**：WorldCat 诚实表述 · 认可度告知 · 真实写作档案非认证 · 预收款分段解锁 + 停业保障条款 · 上架≠销量 · 不主张 CIP · 无独家绑定。
- 内容型：这页文案照《升级版方案》§3.2 与《信息架构.md》§二信任页样板改写。｜开发型：做成可复用的"对比表"+"诚实清单"组件，条目数据化。

## 5.3 出版服务「信用之书」页（**单漏斗主阵地**）
- **目的**：把"一本正规精良、可查证、还被人看得见的书"卖给"书作杠杆"客群（卖课/申博/职业信用者）。
- **区块**：① 承接担忧（按目的分入口小标题：学术→"经得起追问"；卖课/个人品牌→"让你的专业更有分量"）→ ② 能做成什么（成品样子 + 情感承诺 + 两本样书/诗经案例）→ ③ 正规可查证证据（渠道红线：不用 KDP、版权页署社名、LAC 送存、WorldCat 诚实表述、书面"上架≠销量"）+ 学术页含认可度告知 → ④ 交付内容/周期/价格（最后一屏，按 ROI 锚定：对卖课者对标其一门课的收入）→ ⑤ 焊入书后（见 5.5，作为"被看见"的差异点）→ ⑥ CTA。
- **验收**：价格在最后一屏；书后作为套餐内差异点出现，而非另卖给学术客的独立营销品。
- **修法标注**：学术子块认可度告知；渠道红线内嵌；无独家绑定（"你的版权始终是你的"，对比亚洲文化 5 年独家）。
- 内容型：先写"能做成什么 + 案例"，价格块最后写。｜开发型：套餐用数据结构（名称/交付项/周期/价/是否含书后），价格块锚定页面末屏。

## 5.4 真实写作档案页 Authorship Record（**注意：不叫"认证"**）
- **目的**：AI 时代为作者的写作过程留一份诚实、可追溯的档案（卖安心与留痕，不卖"检测报告"）。
- **区块**：① 承接担忧（"AI 时代，怎么证明这是我自己写的"）→ ② 我们做什么（作者签署真实性声明 + 写作过程证据存档：草稿迭代/材料来源/访谈或田野记录 + 一个公开可查证的备案页）→ ③ 诚实边界（"这是过程留痕与声明备案，不是第三方认证；AI 检测存在误差、尤其对中文，故只作内部辅助、不作结论"）→ ④ 价格 → ⑤ CTA。
- **验收**：全页**不出现"认证/certification"作为卖点主张**；不展示"AI 检测分数"作为结论。
- **修法标注**：去检测化；AI 检测降为内部信号；命名统一"档案/声明备案"。
- 内容型：严守用词（档案/声明备案）。｜开发型：备案页做成稳定 URL 的公开可查页（编号 + 声明 + 过程摘要）。

## 5.5 书后计划 Entry / Echo（**第一优先差异化，情感叙事领头**）
- **目的**：让书出版后持续被看见——对"书作杠杆"客群，"被看见"直接=课程/咨询卖得更多。
- **区块**：① 情感承诺领头（「一本书出版之后，才刚刚开始。」「别让它在上架那天就被遗忘。」）→ ② 能做成什么（数字现场/作品页/导读/可分享切片）→ ③ 怎么做到（Entry/Echo 交付项：作品页、社交内容、短视频脚本、导读、发布日历——**作为"证明"列在承诺之后，不领头**）→ ④ 价格 → ⑤ CTA。
- **验收**：情感承诺在最上；"30 条社媒/脚本/SEO-GEO"不作为开头卖点（否则会被拉去和 $200 的 AI 批量内容比价）。
- 内容型：承诺句领头、交付清单靠后。｜开发型：Entry/Echo 两档做成可对比卡片。

## 5.6 选题诊断 Upstream Diagnosis（低价入口）
- **目的**：低门槛入口，判断一个想法能否成书 + 给出路径，筛选并引导到出版/孵化。
- **区块**：① 承接担忧（"你有想写的东西，却不确定它能不能成书"）→ ② 交付（一次深度访谈 + 诊断报告 + 路径建议）→ ③ 价格与抵扣规则（进一步合作可抵扣）→ ④ CTA。
- **验收**：定位为"陪你看清楚"，不是硬销产品；价格透明。
- 内容型：口吻"陪你看清楚"。｜开发型：可接预约/表单。

## 5.7 免费前门「还没想好？先读这里」（Resources 下，读者动线①）
- **目的**：给最大多数"还没准备好"的人一个免费、不催促的入口，做内容获客。
- **区块**：① 「还没想好，也没关系。」→ ② 三份免费读物入口（海外中文作者出版手册 / 哪种作品适合哪条路径 / 别人是怎么开始的）→ ③ 轻 CTA（"等你想更进一步，我们再聊"）。
- **验收**：无付费墙、无催促；付费的选题诊断作为其后的自然下一步而非唯一入口。
- 内容型：先出 3 份读物提纲。｜开发型：可做邮件订阅换 PDF。

## 5.8 服务案例 Case Studies（成交必要条件）
- **目的**：把抽象服务变成"我也能做成"的证据。
- **区块**：① 「看看别人在这里做成了什么。」→ ② 出版服务案例（置顶：两本样书 + 诗经作者「信用之书」样板，每个含封面/书名/书号/年份/上架链接/可查证记录）→ ③ 上游/书后案例 → ④ CTA。每案例补一句"这位作者来时的处境"让读者照见自己。
- **验收**：所有案例真实可查证；不暗示销量承诺；学术案例只呈现"已正式出版"事实。
- 内容型：先做 2–3 个真实案例。｜开发型：案例用结构化数据（封面/书名/ISBN/链接/处境/服务）。

## 5.9 文脉季刊 / 文脉聚合（信任引擎，🟢）
- **目的**：让访客感到"这家出版社是真懂书、有真实作者社群的"，并把作者关系沉淀为暖线索。
- **区块**：期刊介绍 / 最新一期 / 往期目录 / 投稿说明 / 作者与文章 / **文脉聚合**（作者页 + 主题页 + 专题 + 文脉小书）。
- **验收**：投稿说明清晰可用；作者页结构化（简介/发表/研究方向/关键词/可合作方向），与未读物档案"作者档案"同源。
- 内容型：先建首批活跃作者页。｜开发型：作者/文章做成可复用集合，支持主题聚合。

## 5.10 湖岸索引 Oak Index 6+1 初版（Resources，GEO 基础）
- **目的**：主题知识枢纽，成为搜索/AI 答案引擎乐于引用的来源（GEO 优先）。

# 6 · 横切规范（所有页面通用）

## 6.1 品牌系统
- 配色：墨黑 `#1a1614`、暖米纸 `#f5f0e8`、琥珀 `#b87333`、鼠尾草绿 `#4a5e4f`。
- 字体：英文 Cormorant Garamond；中文 Noto Serif SC；双语呈现。
- 气质：冷静、独立、克制、文学、可信；避免廉价 AI 科技感、霓虹渐变、"涨粉/爆单"话术。
- 声音准则：先承接情绪再给方案；用"你"、把术语翻成人话；诚实先行；不催促、不制造稀缺焦虑。

## 6.2 SEO / GEO 基础
- 每个词条/FAQ 给清晰独立可引用的定义段；FAQ 用结构化标记（FAQ schema）；主题枢纽稳定 URL + 清晰标题；内链密集、术语统一。
- 提交 sitemap，接 Search Console。

## 6.3 表单与 CTA
- 全站统一咨询表单（右上角固定 CTA + 每服务页底部 CTA + 页脚 Contact）。
- 服务页底部 CTA 示例：「有一个正在形成的写作计划？预约选题诊断 →」「已经完成书稿？咨询出版服务 →」。
- CTA 用读者口吻领头，不用"立即购买/限时"。

## 6.4 支付集成（依《升级版方案》§5.2 收款研究）
- **约束点在付款方（中国大陆个人）购汇侧**：5 万美元/年额度，付境外服务费属经常项目、允许但**须合同 + 发票**。
- **小额、标准化服务费**：优先 **Stripe 或 PayPal**，让客户用支付宝/微信/银联卡在线支付，平台按 CAD 结算（成本约 3%）。
- **大额**：走 **SWIFT 电汇**，先出正式合同 + 发票，客户以"境外服务费"在额度内付汇。
- **不要**用 PingPong/连连/万里汇（方向相反）。
- 网站侧：定价页标注"支持 支付宝/微信/银联/电汇"，并在下单流程生成合同+发票（款项性质写"出版/编辑/排版服务费"，不写投资类）。
- ⚠️ 加拿大侧 GST/HST（服务出口通常 zero-rated、年营业额超 CAD 30k 注册）与 FINTRAC 报告阈值——**上线收款前须经持牌会计师核实**，未核实前不在站上做税务承诺。

## 6.5 分析与 KPI（GEO 校准）
- KPI 不用"流量"当唯一指标，改跟：**AI 引擎引用出现率 / 品牌词搜索量 / 归因到咨询表单的转化**。
- 埋点：五入口点击、信任页停留、信用之书页 → 咨询表单转化漏斗。

## 6.6 合规文案（诚实边界，须显性上墙）
- 学术页/信任页：认可度告知（海外专著国内评审多为补充、认定权在用人单位、不承诺评上）。
- 出版物回流（若站上涉及"把书带回国内"）：只说"个人自用少量携带/邮寄"的合法路径，**不引导批量进口销售**；要进大陆市场的说法用"授权国内持证出版社出简体版"。（依《升级版方案》§5.1）
- 全站："上架≠销量"、不主张 CIP、无独家绑定——写清楚。

## 6.7 后台注册管理系统集成（复用既有资产，勿重建）
创始人已另行开发一套**后台注册管理系统**，将融合进本开发项目。原则：**复用、集成，不重建**。
- Phase 0 先盘清它的功能 / 接口 / 数据模型 / 认证方式（见 §2 第 7 项）。
- 前台可能的对接点：作者/用户注册与登录、账号中心、咨询与下单记录、（若具备）订单与合同/发票、真实写作档案备案页的数据存储。
- 与 §6.4 支付打通：下单 → 生成合同+发票 → 收款 → 状态回写，尽量走既有后台，避免另造一套。
- 若前后台技术栈不一致，Phase 0 产出集成方案（API 对接 / 同库 / 反向代理等），交创始人确认后再实施。
