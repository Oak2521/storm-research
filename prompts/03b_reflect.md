# Step 3.5 — 反思与补搜 (Reflect & Re-search)

> 作用：首轮检索后，**逐个子问题判断证据够不够；不够就先诊断"差在哪"，再据此调整、补搜**。这是 agentic search 的核心——把检索从一次性动作变成由模型自判充分性的闭环。
> 完整原理见 `reference/agentic-retrieval.md`。

## 核心纪律

**「不够」不是一个布尔值，是一份诊断。** 判定"不够"却只把同一个 query 再搜一遍 = 空转烧 token（over-searching，和漏搜一样是失败）。反思必须输出「差在哪 + 做什么调整」，不是"再来一轮"。

## 流程

```
对每个子问题的检索结果：
  评估充分性
    ├─ 够且一致？ ── 是 ─→ 通过（提前退出，不迭代）
    └─ 否
        ├─ 诊断属于 ①~⑤ 哪一类
        ├─ 选对应调整（见下表）
        └─ 补搜（用 Step 0 清单的工具），轮次 +1
  上限：每子问题 3 轮；到顶仍不够 ─→ 标记缺口、诚实拒答
```

## 诊断 → 调整对照表

| 诊断 | 症状 | 调整动作 |
|------|------|----------|
| ① 跑题/不相关 | query 没命中，结果对不上 | 改写 query：换措辞/术语/中英切换 |
| ② 命中但太浅 | 只有泛泛而谈，缺细节数据 | 下钻：用已有结果里的具体名词生成更细的 query |
| ③ 结果冲突 | 来源互相矛盾 | 定向取证：针对分歧点补搜权威/一手来源 |
| ④ 信源弱/单一 | 全是二手/营销内容 | 换信源：指定抓 arXiv/官方/权威域名 |
| ⑤ 暴露新缺口 | 引出原问题没覆盖的点 | 派生新子问题（计入总预算） |

## 调整的四个杠杆（按优先级）

1. **调 query（最常用）** — 铁律：新 query 必须由"缺口"驱动，**不能重复原 query**。把「原问题 + 已有证据 + 还缺什么」喂回去生成新 query。
2. **调信源/工具** — 换 Step 0 清单里的另一个通道，或直接抓权威域名。
3. **调粒度** — 太宽就收窄下钻，太窄搜空就放宽到上位概念。
4. **派生新子问题** — 仅诊断⑤时，且必须计入预算。

## 3 轮预算：每轮干不同的事

```
第 1 轮：原始 query
第 2 轮：基于第 1 轮诊断调整（改写/换源/下钻）
第 3 轮：最后定向补刀（换信源 / 攻分歧点）
```

## 收场（接抗幻觉红线）

3 轮到顶仍不够：标记「基于现有检索无法充分回答」，写进缺口（feeds Step 5 / Step 8）。**禁止用模型记忆补全。**

## 提前退出（别浪费预算）

**第 1 轮就充分且一致的子问题，直接通过，不进入迭代。** 把 3 轮留给真正难、有争议的问题，别让基础话题（定义/机制/用法）吃掉预算。

## ⚠️ 可见性契约

完成后甩一块紧凑 checkpoint 给用户：
- 哪些子问题第 1 轮就过了；
- 哪些补搜了几轮、每轮的「诊断 → 调整」；
- 哪些到顶仍标记为缺口。

别让这个迭代闭环变成黑箱。

## 为什么这样设计

agentic search 的关键不在"会再搜一次"，而在**搜之前先想清楚缺什么、搜之后判断够没够**。诊断五类对应五种修复，新 query 由缺口驱动而非重复，3 轮预算 + 提前退出双向防住 over/under-searching，到顶诚实标注接住抗幻觉红线。思想源头：Self-RAG / CRAG / FLARE / IRCoT / Adaptive-RAG（见 `reference/agentic-retrieval.md`）。
