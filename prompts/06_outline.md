# Step 5 — 两步法大纲 (Two-Stage Outline)

> 作用：先有结构骨架再注入采集到的深度。**骨架是固定的递进结构——先信息量、后讨论**，避免一上来就堆分歧、读者却还没搞清"是什么、从哪来"。

## 内核

报告必须遵循一条**信息量优先、讨论其次**的递进主线。先凭固定骨架起草，再用采集到的信息精修。

## 固定骨架（报告的递进结构，按此顺序，不可颠倒）

```
（# 摘要 —— 在 Step 6 写，置于全文最前）

一、基础与背景      ← 先搞清来龙去脉
    定义、关键概念、它解决什么问题、起源/发展脉络、相关术语澄清
    重点：信息密度。把"是什么、从哪来"讲到读者无需另查。

二、核心机制 / 全景  ← 再深入整体
    它如何运作、由哪些部分/环节/谱系构成、关键维度与分类、
    主流方案/流派的横向全景。
    重点：把整体讲透，建立读者的全局地图。

三、多视角深入      ← 然后才是丰富讨论（本报告的深度所在）
    每个对立视角一节，且每节用「问题钩子」开场（见下）。
    把 Step 2 各视角的尖锐问题 → 这一层的小节标题。

四、矛盾分析        ← 支撑章节，不是高潮
    跨视角的分歧点、共识项、领域盲区。简明扼要，服务于前三层。

五、（参考来源 + 自查报告，在 Step 6/7 产出）
```

> 顺序纪律：**一、二层负责信息量（事实、定义、机制、全景），三层负责讨论（多视角），四层是支撑。** 不许把矛盾分析提到前面当主菜，也不许跳过一二层直接进多视角。

## 「问题钩子」结构（第三层多视角的写法）

第三层每个小节，用一个**真问题**当标题或开场钩子，然后给出基于检索的答案，带 `[n]` 引用。形如：

```
### LLM 真能自我改进，还是只是把已有能力重新排列？
（一段基于检索的回答，每个论断带 [n]……）
```

钩子问题直接取自 Step 2 各视角提的深问题——它们本就是为"抓住张力"设计的，天然适合做钩子。

## 5a. 草稿大纲（凭固定骨架 + 已知）

```
要写的主题：{TOPIC}

按固定骨架写一份大纲：一、基础与背景；二、核心机制/全景；三、多视角深入（每节一个问题钩子）；四、矛盾分析。
- 用 "#" 一级、"##" 二级、"###" 三级
- 第三层的 "###" 用问题句式（钩子）
- 不含主题名本身、不含引言/结论独立章节
- 只写大纲
```

## 5b. 精修大纲（用采集信息）

```
要写的主题：{TOPIC}
草稿大纲：{5a 输出}
采集到的信息：{Step 3 各问题的带源回答}
矛盾图：{Step 4 输出}

在固定骨架不变的前提下精修：
- 一、二层：用检索到的定义/机制信息把基础和全景补扎实（这是信息量的保证）
- 三层：把 Step 2 的视角问题落成各 "###" 钩子，挂上对应的带源回答
- 四层：把矛盾图的关键分歧浓缩成简明小节
保持 "#" "##" "###" 层级，不含主题名本身。
```

## 5c. 话题完整性核对（兜底）

```
对照 Step 2 覆盖视角的"标准话题清单"，逐条核对大纲：
- 每个标准话题面（定义/机制/证据/用法/同类对比/监管……）是否在「一、基础」或「二、机制」层有承载？
- 缺席的话题：有检索数据 → 补进对应层；无数据 → 标记缺口回 Step 3 补检索，或列入自查。
- 禁止用模型记忆把缺席话题脑补成一段。
```

## 规则

- **骨架顺序固定**：基础 → 机制 → 多视角 → 矛盾。信息量在前，讨论在后。
- 不要单独的 introduction / conclusion 章节（最终由摘要段统领）。
- 第三层每个 "###" 是一个问题钩子，且其下回答必须带 `[n]`。
- 章节标题后面会被当作检索查询用（Step 6），所以一二层标题要具体、可检索。
- **完整性 + 深度都要**：一二层保证基础话题面无缺席（完整性），三层保证分歧点被深挖（深度）。

## 为什么这样设计

读者先要"看懂"，才谈得上"看法"。把定义和机制（信息量）放前面，多视角讨论放后面，矛盾分析降为支撑，符合人理解一个陌生主题的认知顺序——先来龙去脉、再整体、最后才是众说纷纭。问题钩子则把 STORM 攒了一路的视角问题用在刀刃上：既抓读者注意力，又让每段讨论都锚定在一个具体张力上，而不是泛泛而谈。
