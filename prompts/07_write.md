# Step 6 — 带引用写作 (Grounded Section Writing)

> 作用：把可追溯性落地——按固定骨架逐层写作，每个论断内联引用指回真实来源。**先信息量、后讨论**；第三层用问题钩子。

## 写作顺序（按骨架层逐层写，信息量优先）

```
# 摘要              （6b，最后写，置顶）
一、基础与背景      （6a）信息密度优先：定义/概念/来龙去脉
二、核心机制 / 全景  （6a）讲透整体
三、多视角深入      （6a）每节问题钩子 + 带源回答
四、矛盾分析        （6a）简明支撑
## 参考来源         （6c）
## 自查报告         （Step 7）
```

## 6a. 逐章节写作

```
页面主题：{TOPIC}
要写的章节：{SECTION_NAME}（含其子节大纲）
收集的信息（先用本章标题从全局引用表检索相关条目）：
{相关的 [n] 来源 + snippet}

写这个章节，要求：
1. 用 "#" 标章节标题，"##" "###" 标子节
2. 行内用 [1][2]...[n] 标注引用（例："美国的首都是华盛顿特区[1][3]。"）
3. n 对应全局引用表里的真实 URL，不要编造引用号
4. 不写引言/结论章节，不重复页面标题
5. 每个论断都要落在某个 [n] 上；没有来源支撑的论断不要写
```

### 各层的写法侧重

- **一、基础与背景**：信息密度最高的一层。把定义、关键概念、解决什么问题、起源脉络讲到读者无需另查。多用确定性陈述 + 密集引用，少议论。
- **二、核心机制/全景**：建立全局地图。讲清运作方式、组成/谱系、关键维度、主流方案横向对比。仍以陈述事实为主。
- **三、多视角深入（问题钩子）**：这一层才展开讨论。每个 "###" 子节**用一个真问题开场**（取自 Step 2 视角问题），紧接着给出基于检索的回答：

  ```
  ### 它真的有效，还是只是安慰剂效应被放大了？
  <一段直接回答这个问题的内容，每个论断带 [n]。先给最有支撑的答案，
   再点出该视角看到而其他视角忽略的东西。>
  ```

  钩子问题要尖锐、具体、能勾起好奇；回答要落地到证据，不空转。
- **四、矛盾分析**：简明。列分歧点、共识项、盲区，服务于前三层，不喧宾夺主。

## 6b. 摘要引导段（写在报告最前）

```
页面主题：{TOPIC}
完整草稿：{所有章节}

写一段引导摘要：
1. 作为全文的简明概述，能独立成段
2. 点明主题、确立背景、说明为何重要、概括最重要的点（含主要争议）
3. 可用 1-2 个核心问题开场做钩子，但随即给出概括性回答
4. 不超过 4 段，恰当处加 [n] 引用
```

## 6c. 参考来源列表（文末，必须有）

```
在报告末尾输出 `## 参考来源`：
把全局引用表里所有出现过的 [n]，按编号列出真实 URL：
[1] {title} — {url}
[2] {title} — {url}
...
核对：正文里出现的每个 [n]，这里都要能找到对应条目。
```

## 规则

- **层序不可乱**：基础 → 机制 → 多视角 → 矛盾。信息量在前，讨论在后。
- 每章先做"标题 → 检索引用表"的映射，只用相关来源，避免无关信息稀释。
- 内联引用号必须对得上 Step 3 的全局引用表。写完核对：报告里每个 [n] 都能在参考来源列表找到。
- 第三层每个子节必须是"问题钩子 + 带源回答"的形态。
- 多个章节可分别独立写，最后按骨架顺序拼装。

## 为什么这样设计

强制内联引用是可追溯性的落地。固定的层序（先信息量、后讨论）保证读者先搞懂来龙去脉再进入分歧，避免"还没看懂就被砸一堆观点"。问题钩子让第三层的每段讨论都锚在一个具体张力上，既抓注意力又防泛泛而谈——这正是 STORM 多视角提问的价值在成文阶段的兑现。
