# Agentic 检索：反思与补搜（Reflect & Re-search）

> 这份文档讲清楚 storm-research 里最难、也最关键的一环：**首轮检索之后，模型如何判断证据够不够，以及"不够"时具体该怎么调整再搜。** 对应流程里的 **Step 3.5（反思补搜）**。

## 为什么需要这一步

搜索类系统有两大挑战：

1. **问题理解与多视角拆解** —— "从哪些角度问"。storm-research 用 **persona（Step 1）+ query 拆解（Step 2）** 解决，这是研究的广度与深度来源。
2. **agentic 闭环** —— "问完、看了结果之后，还缺什么、要不要接着问、什么时候收手"。这才是真正的难点。

第二点的本质，是把检索从**一次性动作**变成**由模型自己判断充分性、自己决定再搜什么的闭环**。这正是 naive RAG 与 agentic search 的分界线：naive RAG 的检索是固定的、在模型控制之外；agentic search 里，模型自己决定要不要搜、搜什么、什么时候停。

学术界对这条线的核心命题收敛得很清楚：

> **该搜什么，取决于你已经搜到 / 推理出了什么。** 一次性拆完、各搜一轮就收工是不够的（IRCoT, ReAct）。

## 核心纪律：「不够」不是一个布尔值，是一份诊断

最常见的错误，是把"不够"当成单一状态，于是"不够"时只会**把同一个 query 再搜一遍**——这等于空转烧 token，正是 Anthropic 多 agent 系统点名的失败模式：**over-searching（过度搜索）和 under-searching 一样是失败**。

所以反思那一步真正该输出的，不是"够 / 不够"，而是**"差在哪" + "对应做什么调整"**。

---

## 一、诊断：把「不够」分成五类

反思每个子问题的检索结果时，先判断它落在哪一类（借 CRAG 的"给检索结果分档"精神）：

| # | 诊断 | 症状 | 对应调整 |
|---|------|------|----------|
| ① | **跑题 / 不相关**（irrelevant） | 结果和问题对不上，query 没命中 | **改写 query**：换措辞、换术语、中英切换——不是重搜原词 |
| ② | **命中但太浅**（insufficient depth） | 搜到了主题，但只有泛泛而谈，没有细节/数据 | **下钻**：用已有结果里的具体名词/概念，生成更具体的子 query |
| ③ | **结果互相冲突**（conflicting） | 不同来源说法矛盾，无法定论 | **定向取证**：针对分歧点补搜权威源/一手来源，去裁决 |
| ④ | **信源弱 / 单一**（low authority） | 全是二手博客、营销内容，没有权威支撑 | **换信源**：指定抓 arXiv / 官方文档 / 权威域名 |
| ⑤ | **暴露了新缺口**（new gap） | 结果引出了一个原问题没覆盖的子问题 | **派生新子问题**，加入队列（受总预算约束，否则无限膨胀） |

诊断先行的意义：五类的修复动作完全不同。不诊断就补搜，等于盲目重试。

---

## 二、调整：补搜时可调的四个杠杆

判定要补搜后，可调的就这四样，按优先级：

1. **调 query 本身（最常用）**
   - **铁律：新 query 必须由"缺口"驱动，不能重复原 query。** 把「原问题 + 已搜到的证据 + 还缺什么」喂回模型生成新 query（FLARE / IRCoT 的精神：该搜什么取决于已经搜到了什么）。
   - 手法：换同义词/术语、中英切换、加限定词下钻、把一个大问题拆成更小的点。

2. **调信源 / 工具**
   - 换一个检索通道（Step 0 清单里的另一个工具），或直接对权威域名抓正文。
   - 对应诊断 ① ④。

3. **调粒度**
   - 上一轮太宽（结果泛泛）→ 收窄、下钻具体；上一轮太窄（搜空了）→ 放宽、退一步搜上位概念。
   - 对应诊断 ②。

4. **派生新子问题**
   - 仅在诊断 ⑤ 时做，且**必须计入总预算**，否则问题队列会无限膨胀。

---

## 三、预算：每子问题最多 3 轮，且每轮干不同的事

迭代预算的思想来自 Adaptive-RAG（按问题复杂度路由检索强度）。关键不是"最多 3 轮"这个数字，而是**每一轮必须干不同的事**，否则 3 轮退化成 3 次重复：

```
第 1 轮：原始 query（persona 提的问题转的搜索词）
第 2 轮：基于第 1 轮诊断做调整（改写 / 换源 / 下钻）
第 3 轮：最后一次定向补刀（通常是换信源，或攻分歧点）
```

**3 轮后仍不够 → 不许再搜，必须 stop。**

---

## 四、收场：到顶仍不够，诚实标注，绝不脑补

这一步直接接 storm-research 的抗幻觉红线。3 轮到顶仍不充分时：

- 把该子问题标记为 **「基于现有检索无法充分回答」**，写进缺口（feeds Step 5 矛盾图 / 缺口、Step 8 自查报告）。
- **禁止用模型记忆补全。** over-searching（空转）和 hallucination（脑补）是这一步的两个失败方向，都要堵死。

---

## 五、别在简单问题上浪费 3 轮（提前退出）

不是每个子问题都值得迭代（Adaptive-RAG 的核心提醒）。加一个轻量提前退出：

> **第 1 轮就搜到「充分且一致」的子问题，直接通过，不进入反思补搜。**

把 3 轮预算留给真正难的、有争议的子问题。否则覆盖视角那一堆基础话题（定义/机制/用法…）会白白吃掉预算。

---

## 六、落到流程：Step 3.5 的闭环

```
对每个子问题的检索结果：
  评估充分性
    ├─ 够且一致？ ── 是 ─→ 通过（提前退出，不迭代）
    └─ 否
        ├─ 诊断属于 ①~⑤ 哪一类
        ├─ 选对应调整（改写 query / 换源 / 调粒度 / 派生子问题）
        └─ 补搜，轮次 +1
  循环上限：每子问题 3 轮
  到顶仍不够 ─→ 标记缺口、诚实拒答 ─→ 进入 Step 4 作答
```

### 可见性契约（这一步同样不能变黑箱）

Step 3.5 完成后，给用户甩一块紧凑 checkpoint：

- 哪些子问题**第 1 轮就过了**（提前退出）；
- 哪些**补搜了几轮**、每轮做了什么调整（诊断 → 动作）；
- 哪些**到顶仍标记为缺口**（诚实拒答）。

否则这个迭代闭环又退化成用户看不懂的黑箱。

## 思想源头（均为一手论文 / 官方工程文档）

- **Self-RAG**（反思 token：ISREL 相关性 / ISSUP 支撑度 / ISUSE 有用性，按需检索）— https://arxiv.org/abs/2310.11511
- **CRAG / Corrective RAG**（检索结果评估器三分档：correct→精炼 / incorrect→转网搜 / ambiguous→结合）— https://arxiv.org/abs/2401.15884
- **FLARE / Active RAG**（生成时遇低置信 token 才触发检索，用预测句当 query）— https://arxiv.org/abs/2305.06983
- **IRCoT**（推理与检索交替：该搜什么取决于已推理出什么）— https://arxiv.org/abs/2212.10509
- **ReAct**（think → act/search → observe 循环，现代 search agent 的骨架）— https://arxiv.org/abs/2210.03629
- **Adaptive-RAG**（按 query 复杂度路由：不检索 / 单步 / 多步迭代，控制迭代预算）— https://arxiv.org/abs/2403.14403
- **Agentic RAG Survey**（agentic 四模式：反思 / 规划 / 工具使用 / 多 agent 协作）— https://arxiv.org/abs/2501.09136
- **Anthropic — How we built our multi-agent research system**（over-searching 是常见失败；effort 随复杂度缩放）— https://www.anthropic.com/engineering/built-multi-agent-research-system
